# ORCA parser fixtures (fixtures/orca/)

This directory holds the regression fixtures of the parser layer
(`src/fblockkit/parsers/orca.py`). Every fixture records its source and its conventions
-- every regular expression in the parser must be checked against the real output here
and never written from a manual example (manual examples can come from older versions:
the CASPT2 Reference Weight line style has changed in 6.1.1, for instance).

## How the SOC markers were fixed (recorded, to prevent regression)

The initial candidate markers were falsified one by one on the fixtures:

- a bare `SOC`: the author list at the top of an ORCA output contains "Local ZFS, SOC",
  so it is always true and unusable;
- `QDPT`: a comment line in NEVPT2/CASPT2 output contains "MRCI SOC BLOCK INPUT ... QDPT
  treatment", a false positive;
- `SOC integrals` / `SOC RMEs`: the timings lines of the perturbation module contain them
  too, false positives;
- adopted: `Calculating SOCInts`, `Doing QDPT with ONLY SOC`, `NONZERO SOC MATRIX ELEMENTS`,
  `SOC CORRECTED`, `SOC MATRIX`, `Lowest eigenvalue of the SOC matrix`
  -- verified against every fixture: they hit in SOC jobs and never in non-SOC jobs. The
  minimal-printing fixture `co_plus_soc_min.out` (`PrintLevel 1`, no SOC matrix printed)
  still hits four of them in practice (`Calculating SOCInts`, `Doing QDPT with ONLY SOC`,
  `SOC CORRECTED`, `Lowest eigenvalue of the SOC matrix`), so detection holds at the lower
  printing bound.

## Known-behaviour notes

- `generated_ce3_sarc2.out`: the active occupations are (1,0,0,0,0,0,0) -- putting the
  whole f shell of an f1 system into the window is "by design", but it does trigger
  `DG-ACTIVE-SPACE-NEAR-EMPTY` (an active orbital with occupation < 0.02). That conclusion
  is a warn-level "please confirm" rather than an error: taking the whole f shell into the
  window is a routine choice in magnetic/spectroscopic studies. The same applies to the
  analogous case (a nearly full orbital).
- `ce3_orbcomp.out` (and every run of the same input): **this calculation landed on the d1
  solution** -- A1 composition analysis gives the singly occupied active orbital as 100%
  Ce-d (dz2/dyz/dx2-y2) with all seven 4f orbitals virtual (occ = 0). That is, the
  ROHF/CASSCF initial guess put the single electron into 5d rather than 4f (another
  instance of this group's "multiple solutions" experience). Use: a regression sample for
  A1 detecting "the active-orbital composition does not match the target"; if the target is
  the 4f1 solution, the initial guess must be changed (fragment guess / explicit active
  orbitals) or the calculation restarted from several starting points -- a candidate
  diagnostic rule, not implemented yet.

## Discipline for extending the fixtures

A new fixture must (1) keep the original output bytes without trimming; (2) be registered
in this table with its source and the points it covers; (3) run `pytest` against these
fixtures before any change to a parser regular expression.
