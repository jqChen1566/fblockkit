# pysisyphus fixtures (fixtures/pysisyphus/)

The regression fixtures of the B-layer pair "generate its input / read its output"
(`src/fblockkit/parsers/pysisyphus.py`, `src/fblockkit/analysis/pysisyphus_run.py`,
menus 32/33).  The other program is **pysisyphus 1.0.0** (GPL-3.0,
`github.com/eljost/pysisyphus`, release of 2025-08-31), driving **ORCA 6.1.1** as
its calculator.  Everything here is a verbatim copy of a real run on server 101,
2026-09-28; nothing is hand-edited.

## How the runs were made (reproducible on 101)

- pysisyphus was deployed without touching the system: the release tarball
  extracted under `/data1/cjq12/pysisyphus-1.0.0/` (a `version.py` with
  `version = "1.0.0"` added, since it is generated by the build), a venv
  `--system-site-packages` at `/data1/cjq12/pysis_venv/` with the few missing
  pure-Python dependencies (natsort, rmsd, autograd, optuna, alembic, mako),
  and the runs launched as
  `PYSISRC=<a pysisyphusrc with [orca5] cmd=/home/chen_jianqi/orca/orca_6_1_1/orca> \
   PYTHONPATH=/data1/cjq12/pysisyphus-1.0.0 python -m pysisyphus.run <input>.yaml`.
- pysisyphus stages each calculator call in a temporary directory under `$TMPDIR`
  (observed: `/data2/SCR/...`) and copies the kept files into `qm_calcs/` at the
  end of the call; the `qm_calcs/cur_out` symlink points into that scratch and
  dangles afterwards.

| Directory | Input | Job | Outcome (marker) | Parsing points covered |
|---|---|---|---|---|
| `h2o_opt/` | `h2o_opt.yaml` (redund, `orca5`, `hf def2-svp`, pal 2) | minimum optimisation (rfo, thresh gau) | converged (4 cycles, 21 s) | console banner/cycle table/final summary, `.trj` energy comments, `RUN.yaml`, per-cycle ORCA outputs, the four cross-checks |
| `butadiene_ts/` | `butadiene_ts.yaml` (inline geometry; rsprfo, `hessian_init: fischer`, rx_modes) | TS search, Baker test-set case 11 at HF/3-21G | converged (20 cycles, 2 min 41 s) | the TS banner, the **table split** (rows 0-9, dashes, rows 10-19), `ts_optimization.trj` / `ts_final_geometry.xyz` / `ts_opt.xyz`, group `tsopt` |
| `h2o_stop3/` | `h2o_stop3.yaml` (same job, `max_cycles: 3`) | minimum optimisation stopped by the cycle limit | **`Number of cycles exceeded!`** -- while the closing forces already sit below the thresholds (the marker is the outcome, not the force values) | the non-converged path; the **extra closing evaluation**: 3 cycle rows against 4 calculator calls, the run's last call belonging to the closing state |
| `hess_crash/` | `h2o_opt_hess.yaml` (the same H2O job with `do_hess: true`) | the optimisation converged, then the **final-Hessian** post-processing crashed | `RunAfterCalculationFailedException` -- class: the ORCA-6 Hessian parse stop | the crash traceback, the `crashed_calculator_000/` backup, and the `$multiplicity` signature in its `orca.hess` |

Cross-checks the fixtures pin down (all asserted in `tests/test_pysisyphus.py`):

- the trajectory has one frame per cycle row (4/4, 20/20, 3/3, 4/4);
- the closing frame's energy equals the ORCA energy of the calculator call that
  produced it (the run's last call when it converged there; the second-to-last
  one in the stopped run);
- the `Final summary` energy equals the **last** calculator call (in the stopped
  run that is the extra closing evaluation; in the crash run the last surviving
  call, the crashed Hessian call having gone to the backup directory);
- the closing geometry file reproduces the closing state (energy; and for the
  converged runs also the coordinates of the closing frame);
- `butadiene_ts/` reproduces the energy asserted in pysisyphus's own example set
  for this case (`assert: ts_geom.energy: -154.050455732882` in
  `examples/tsopt/06_orca_baker_ts_trans_butadiene/`) to 7e-8
  (our run: **-154.05045566 Eh**; the small difference is the initial Hessian
  route: the example uses the quantum Hessian, this run a model Hessian).

## Measured format conventions (why the reader looks the way it does)

- Frame comments carry the energy as `f"{energy: >20.8f} , "` (pysisyphus's
  `Geometry.comment` property), so the trajectory energy and the console table
  agree at 8 decimals.
- The console cycle table **restarts after every ten rows** with a dashes
  separator and no repeated header (measured on `butadiene_ts/`: 20 cycles).
- `final_geometry.xyz` has **no trailing newline**; the `.trj` frames are
  separated by a single newline.
- The `$multiplicity` block the ORCA-6 `.hess` writer adds is not in
  pysisyphus's Hessian grammar (measured identical in release 1.0.0 and on the
  master branch): `pyparsing` stops with `Expected W:(0-9), found '$'`, and the
  post-processing raises.  Consequences: `hessian_init: calc` (the `tsopt`
  default) and `do_hess` are unusable with ORCA 6.1.1; everything
  gradient-driven (via ORCA's `.engrad` sidecar) is unaffected.
- `optimization.h5` (kept in the fixtures for completeness) is the structured
  history; the reader does **not** parse it (HDF5; h5py is not a dependency of
  this toolkit) -- the text artifacts carry the same numbers.
